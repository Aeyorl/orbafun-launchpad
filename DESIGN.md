# Orba Design Direction

This file defines the permanent visual-reference order for Orba product and website work. It applies to new screens, redesigns, visual audits, and component polish.

## Reference priority

Use design sources in this order:

1. **Orba-specific approved references** — supplied Figma files, screenshots, prototypes, and existing production patterns for the feature being changed.
2. **Super Visuals — Backgrounds Library** — [Figma source](https://www.figma.com/design/1RjQY50dy7t9SucZtAIb1p/Super-Visuals--Backgrounds-Library). Use it first for expressive backgrounds, atmospheric layers, gradients, texture, and visual depth. Adapt the work to Orba's brand and accessibility requirements; do not copy assets without permission.
3. **Inspora** — [inspora.design](https://www.inspora.design/). Use it for product-interface composition, information hierarchy, data presentation, interaction patterns, and contemporary visual references. Select and record the specific reference used for each meaningful design change.
4. **Orba's existing design system** — preserve established typography, tokens, components, responsive behavior, and transaction semantics unless an approved reference calls for a deliberate evolution.
5. **Refero Styles** — fallback inspiration only when the higher-priority sources do not cover the design problem.

The Figma Super Visuals library and Inspora must always be considered before Refero. Refero must not determine a design direction when either higher-priority source provides a suitable reference.

## Adaptation rules

- Treat references as visual evidence, not templates to clone blindly.
- Keep Orba's editorial identity and transaction clarity recognizable.
- Preserve accessibility, keyboard operation, responsive layouts, clear live-update behavior, and non-color-only buy/sell communication.
- Use real brand assets or licensed/source assets. Do not approximate visible artwork with emoji, CSS art, or handmade placeholder graphics.
- Record the chosen reference and the translated principles in the implementation or design QA notes.
