## Steps to Deploy on Render

### Step 1 — Go to Render Blueprints
Visit [https://dashboard.render.com/blueprints](https://dashboard.render.com/blueprints) → **New Blueprint** → select the `Aeyod7/orbafun-launchpad` repo

### Step 2 — Provide Secrets (sync: false env vars)
When Render prompts for each secret (blueprint wizard):

| Field | Value to Paste |
|---|---|
| `CORS_ORIGIN` | `https://orba.fun` |
| `AUTH_SECRET` | Generate: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `DEPLOYER_PRIVATE_KEY` | Testnet deployer wallet private key (never share!) |
| `ADMIN_WALLETS` | Comma-separated EVM addresses allowed to register agents |
| `PINATA_JWT` | (Optional) Free from https://app.pinata.cloud for token image uploads |

### Step 3 — After Blueprint Creates Services
In Render dashboard → Environment tab, add these additional env vars to the API service:

```
CORS_ORIGIN=https://orba.fun,https://orbafun-launchpad-web.vercel.app,http://localhost:3000
```

### Step 4 — Set Frontend Env Vars on Vercel
After API is live, go to Vercel → Project → Settings → Environment Variables:

| Key | Value |
|---|---|
| `NEXT_PUBLIC_API_URL` | `https://orba-api.onrender.com` |
| `NEXT_PUBLIC_WS_URL` | `https://orba-api.onrender.com` |
| `NEXT_PUBLIC_SITE_URL` | `https://orba.fun` |
| `NEXT_PUBLIC_ARC_RPC_URLS` | `https://rpc.testnet.arc.io,https://rpc.drpc.testnet.arc.io,https://rpc.quicknode.testnet.arc.io,https://rpc.blockdaemon.testnet.arc.io` |

Then redeploy the frontend.

### Step 5 — Verify
```bash
curl https://orba-api.onrender.com/tokens?limit=1
# Should return JSON array, not 404
```

### Pricing
- Postgres `basic-256mb`: ~$7/mo
- API `starter`: ~$7/mo (always-on needed for indexer + WebSocket)
- Redis `free`: $0
- **Total: ~$14/mo**

### Important Notes
- `AUTH_ALLOW_INSECURE=true` is set in blueprint — safe for testnet. **Must be false before mainnet.**
- Render free tier **won't work** for the API — it spins down after 15 min inactivity, killing the indexer poller and WebSocket server.
- The API's health check starts returning 200 only after the DB migration runs on first boot (~30s).
